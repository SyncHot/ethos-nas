# Docker Manager + Docker Engine provisioning

> **Status (2026-11-15):** the desktop app now ships as the package `ethos-docker`
> (`runtime: files`, native UI). The **engine** side stays in core —
> `services/docker_host.py`, the privileged helper `ethos-docker-install`, the compose runtime and
> `/api/docker/*` — because every container package depends on them and a package cannot manage the
> host engine. This document describes the core half; the UI lives in
> `ethos-packages/ethos-docker`.

Fresh-server story: EthOS should be able to provision Docker Engine + Compose v2 itself, and the
built-in Docker app should explain and repair its own prerequisites instead of failing with
“Docker daemon is not reachable”.

## Why the engine cannot be a package

Packages are signed, compose-only bundles: `services/compose_policy.py` rejects
`privileged`, `cap_add`, host networking, `devices:` and any bind of `/var/run/docker.sock`. A
package therefore **cannot** manage the host engine. The engine provisioning stays in core and
packages *declare* the engine as a requirement (`system_requires: ["docker"]`) instead. The app UI,
which only talks to `/api/docker/*`, is a normal package (`ethos-docker`).

| File | Role |

| `backend/routers/system.py` | `/api/system/doctor` reports engine, Compose plugin and group access |

| `setup_scripts/install.sh` | installs Docker on a fresh server (`ETHOS_SKIP_DOCKER=1` opts out) |

## Privilege model

Docker installation needs root; the service user gets **no** apt access. The only new privilege is one
argument-free sudoers rule:

```text
ethos-nas ALL=(root) NOPASSWD: /usr/local/bin/ethos-docker-install
```

The helper is generated by `setup_service.sh` (same pattern as `ethos-usb-partition`), takes **no**
parameters, and:

1. refuses non-root, non-Ubuntu/Debian, unsupported architectures;
2. is idempotent — a working `docker` + `docker compose` exits 0;
3. refuses to touch `podman`, snap Docker or a distro `docker.io` install;
4. installs Docker’s apt key into `/etc/apt/keyrings/docker.asc` after checking its **fingerprint**
   (`9DC858229FC7DD38854AE2D88D81803C0EBFCD88`);
5. installs `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`;
6. `systemctl enable --now docker`, then `usermod -aG docker ethos-nas`.

Group membership only applies to new processes, so the last step requires a restart. The job ends with
`restart_required` and the app shows a **Restart EthOS** button (`POST /api/system/restart`); the
backend never restarts itself.

## API

| Endpoint | Auth | Notes |
|---|---|---|
| `GET /api/docker/engine` | any JWT | `cli, daemon, version, compose, socket{path,exists}, group_member, group_granted, restart_required, helper, install_supported, conflict, os{id,version}` |
| `POST /api/docker/engine/install` | admin | returns `{job_id}`; `503` when the helper is missing (detail names the setup command); `409` on an engine conflict |
| `GET /api/docker/engine/jobs/{id}` | any JWT | same shape as `/api/packages/jobs/{id}`; only jobs owned by `system:docker` |

Job steps: `check → install → verify → done` (`services/package_jobs.STEP_PLANS`).

## Package integration

`manifest.system_requires` (allowlist `["docker"]`) makes the engine an install dependency:

* `install`/`update` plans run `deps` right after `policy`;
* `docker_host.ensure_system_deps()` is synchronous and called through `asyncio.to_thread`;
* if the engine is missing and the helper is present, it is installed first (the installer is already
  admin-only);
* if the helper is missing, the job fails with an actionable message pointing at the Docker Manager,
  staging is removed and no record is written.

Packages with no `system_requires` never probe the engine.

## Docker app states

| State | UI |
|---|---|
| `daemon` true | normal tabs + `v<engine> · compose v<compose>` subtitle |
| not installed, helper present | **Install Docker Engine** (admin) → job progress → restart prompt |
| not installed, helper missing | copyable `sudo bash setup_scripts/setup_service.sh` |
| `restart_required` | diagnostics + **Restart EthOS** |
| `conflict` (podman / snap docker / docker.io) | explanation, no install button |
| unsupported OS | explanation, no install button |

Non-admins see the diagnosis but no action buttons.

## Limitations

- Only Docker is provisionable; arbitrary apt packages (ffmpeg, etc.) are out of scope.
- Removal/downgrade of Docker, offline installs and `data-root` relocation are not supported.
- The helper refuses to uninstall conflicting engines; the operator resolves them.
- `WS /ws/logs/*` is admin-only (4003 for other roles) and returns JSON frames; `terminal.py`
  `container:<name>` exec remains readable by any authenticated user (tracked separately).
